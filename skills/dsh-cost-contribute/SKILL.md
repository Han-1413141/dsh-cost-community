# DSH 成本与工作摘要贡献

由当前会话完成整理、预览和直传。用户只需补充缺失事实、查看摘要，并确认当前版本；不要要求用户打开网页导入文件或手写 JSON。

脚本路径均相对于本 `SKILL.md` 所在目录。使用 Node.js 22 或 24；运行 `node --version` 检查即可。无需安装 npm 依赖。

## 整理本地草稿

1. 确认用户要贡献的日期、项目或任务范围。只读取这次授权范围内的工作记录与统计，不扫描其他项目、对话历史或凭据。已有上下文足够时直接整理。
2. 需要读取插件账本时，使用 `scripts/client/collect-dsh.mjs`。先读其 `--help`，传入已确认的 DSH 根目录及日期范围。它只生成本地观察记录，不自动认定账单实付、任务验收或完整周期。已在当前会话掌握的数据不必重复读取。
3. 组装数据前按需阅读 [字段与统计口径](references/data.md)。依据真实记录生成 UTF-8 v2 JSON，保存于本地工作目录；缺少实付、验收、完整周期或任务对应关系时，只追问这些缺项。仅贡献额度样本时，不要求补充无关的实付账单与任务验收，也不把未提供显示为零。API 等价费用不是实付；未知数不填零。不能确认周期完整时保留本地草稿，不设完整标记上传。
4. 功能只保留通用类别，代码量只保留区间，难度与所属周期一致。项目名称、客户名称、业务细节、源码、路径、精确代码行数不进入数据。不要把原文另发给外部模型或脱敏服务。删除工作摘要时保留该任务的成本、尝试与验收记录。
5. 使用新的草稿目录运行：

```text
node "<技能目录>/scripts/client/dsh-cost-contribute.mjs" prepare --input "<本地v2.json>" --out "<新草稿目录>"
```

`prepare` 不联网。它先校验，再替换任务、额度窗口和工作流标识，生成 `preview.md`、`payload.json` 和 `manifest.json`。不要把演示数据改成真实数据上传。

## 让用户查看并确认

在当前对话按本次实际包含的数据展示简明预览：统计范围、实付金额、不同任务数与已验收数、每项工作的功能类别／代码量区间／难度／验收结果，以及 Token 和额度统计。只含额度样本时，仅展示额度与 Token 部分，不显示“0 项任务”或“0 元实付”。给出完整 `preview.md` 与实际待发 `payload.json` 的本地文件链接，标明草稿版本（`review_sha256` 前 12 位）。任务较多时在文件中完整列出，正文概括总数与分布。

说明“向 dsh-cost-community 发送这些去标识的统计记录；服务端重算后保存周期与额度汇总，达到公开门槛后参与聚合比较”。用户可改类别、改区间或删去工作摘要。若改了任何待发内容，重新 `prepare` 到新目录，再展示新版本；旧确认失效。

**必须等用户看过这一版并明确同意上传。** “确认上传这一版”等自然语言即可，不让用户复述整个哈希。读取本版 `manifest.json` 的 `review_sha256`，只上传已获确认的草稿：

```text
node "<技能目录>/scripts/client/dsh-cost-contribute.mjs" upload --draft "<已确认草稿目录>" --confirmed-sha256 "<该版完整review_sha256>" --confirm-reviewed
```

不要在用户确认前调用 `upload`。哈希用于锁定预览版本，不能代替用户同意。上传地址固定为 `https://dsh-cost-community.onrender.com`；不改成其他服务。

## 完成或撤回

上传成功后给出贡献编号、服务端摘要文件和本机撤回凭证路径。凭证是私密文件，不展示密钥、不提交到仓库、不附进报告。结果不明时保留状态并报告，不自动重传。服务拒绝或不可用时保留草稿并说明实际原因，不宣称成功。

仅在用户要求撤回该贡献时运行：

```text
node "<技能目录>/scripts/client/dsh-cost-contribute.mjs" withdraw --receipt "<本机撤回凭证.json>" --confirm-withdraw
```

用户没有要求贡献时，本技能不自动上传任何任务统计。
